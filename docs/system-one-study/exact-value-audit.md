## Same-evidence provider probe

I fixed the correct sources and nearby distractors before running 28 live requests with Perplexity Decider v1.3 and Flash v1.3. Each arm received the same evidence sheet for a case. The seven cases were the repository cell, the exact Kelvin span, the explicitly scoped approximate Kelvin cell, the exact Kelvin request with the exact prose withheld, and the README, WCAG, and Git switch strings above. The probe preselects candidate spans. It measures the decision step only, with one trial per case, model, and arm. It does not measure production retrieval, list completeness, browser capture, or fallback latency.

The structured arm uses one choice with an explicit none option and one predicate per candidate, packed into one request. It copies the chosen local span only if that candidate is the only predicate at or above 0.5. The Locate arm submits the same sheet and requires the top returned span to align with a candidate's exact Unicode code-point offsets and text.

| Arm                    | Correct positive | Correct absent | Wrong accept | Positive abstentions | Median / max decision time | Input tokens |
| ---------------------- | ---------------: | -------------: | -----------: | -------------------: | -------------------------: | -----------: |
| Choice + predicates    |            11/12 |            1/2 |            1 |                    1 |               537 / 919 ms |        7,590 |
| Locate + exact offsets |             9/12 |            1/2 |            1 |                    3 |               465 / 789 ms |        3,328 |

- On the absent control, Decider chose the triple-point `273.16 K` in both arms. Its predicate scored 0.721 and its exact span scored 0.874. Flash chose the formula's `273.15` in the structured arm. The predicates rejected all three candidates, so Flash abstained.
- On the positive NIST control, Flash chose the correct prose but also rated the formula candidate 0.626. The uniqueness rule abstained. Flash Locate returned no span. Both models returned the rounded cell in both arms when asked for that specific table.
- Flash Locate returned no span for the two-line README example and included a preceding line in the Git output span. The structured arm copied both correctly. The two arms and both models copied the GitHub qualifier and WCAG visible text once the literal text was in their evidence.
- The structured predicates removed one wrong accept and one correct accept. They are separate questions in the same request. The probe gives no basis for treating them as independent evidence.

## Next change and release tests

- After a scope and slot have passed existing selection, read the selected cells or explicit visible-text elements in one bounded DOM batch per frame. Retain document and frame identity, source ID, locator, and text kind. Copy a complete literal span before schema conversion. Preserve case, punctuation, internal line breaks, tabs, and meaningful spaces. Apply boundary trim only where the requested value permits it. Keep accessible names for requests that ask for them.
- Give the DOM read a short budget inside the existing extraction deadline. Start with the current list size limit on the heading-scoped path. Measure added p50 and p95 in shadow with a proposed p95 budget of 50 ms. These timings exclude DOM reads. Exact copying should add zero model requests. A stale document, missing or hidden source, ambiguous locator, or capped span should leave exact extraction unresolved and use existing fallback or omission behavior. It should never repair punctuation or join fragments by guesswork.
- Exercise the table order and two forms of accessible versus visible text in the source table above. Add stale and wrong-frame IDs, a meaningful space and a zero-width break, a truncated source, and two nearby matches with the same displayed value but different meaning. Require every accepted string to map back to its exact source and keep existing fallback coverage.
- For scalar work in shadow, carry the original exact span, section or table label, row, column, unit, and surrounding prose into the decision. Include conflicting fact types in the same bounded candidate set. For NIST, include the approximate row, exact formula, and triple-point distractor in every precision test. Require both correct positive cases and zero wrong accepts on the withheld-prose control before enabling direct accepts. Re-run the ordinary freezing-point instruction from the archive as well as the probe's explicitly exact variant.

## Reproduce

Run from the checkout root with workspace dependencies and the local vendor archive. Omit `--live` to print the pinned candidates and run the outline/DOM assertions without a provider call. For live mode, use the existing Perplexity environment key.

```sh
vendor=/Users/vishal/Developer/personal/forks/stagehand/vendor-repos
probe=packages/sdk-ts/scripts/system-one-exact-audit/probe.ts
node --import tsx "$probe" "$vendor"
node --env-file="$vendor/../.env" --import tsx "$probe" "$vendor" --live > results.jsonl
```

The initial live result JSONL has SHA-256 `a212aea3379117f186d1bfcfa5e35d3b7e544fcf7fe07e09aa79695bf513e1ff`. The runner verifies both older capture hashes and the section manifest's capture hashes. It logs public evidence, choices, offsets, timings, and token usage without logging credentials.
